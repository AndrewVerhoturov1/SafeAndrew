# Skill: запись питания и стомы из короткого сообщения

## Назначение

Использовать этот skill для коротких пользовательских сообщений, в которых пользователь сообщает:

- что он съел;
- что он выпил;
- что вышло по стоме;
- наблюдаемые характеристики отделяемого;
- несколько таких событий в одной фразе.

Это **capture-only skill**. Его задача — запись фактов, а не анализ.

Канонический контракт:

`system/voice-food-stoma-capture-contract.md`

---

## Обязательное чтение

Для обычной записи достаточно:

1. `AGENTS.md`;
2. `system/voice-food-stoma-capture-contract.md`;
3. `09 Ежедневный контроль/Питание и стома/README.md`;
4. текущий дневной файл, если он уже существует.

Не читать научную базу, гипотезы, медицинскую картину и другие разделы, если пользователь отдельно не просил анализ.

---

## Алгоритм

### Шаг 1. Определи, является ли сообщение записью

Если пользователь просто сообщает факт о питании/питье/стоме и не задаёт вопрос — считать это командой записи.

Не требовать слов `запиши` или `сохрани`.

### Шаг 2. Извлеки только факты

Сохраняй только явно сообщённое.

Не достраивай медицинский смысл.

### Шаг 3. Разреши дату и время

Приоритет:

1. явное время пользователя;
2. относительное время пользователя;
3. текущее локальное время сообщения для текущего события.

Не спрашивай время, если событие описано как текущее.

Не выдумывай точное время для слов `утром`, `вечером`, `после обеда`.

### Шаг 4. Определи файл

Путь:

`09 Ежедневный контроль/Питание и стома/YYYY-MM-DD.md`

Если файла нет — создать по шаблону:

`templates/Шаблон журнала питания и стомы.md`

Если файл есть — сначала прочитать его.

### Шаг 5. Добавь событие

Формат:

```md
- HH:MM — **Питание:** ...
- HH:MM — **Питьё:** ...
- HH:MM — **Стома:** ...
```

Сохраняй маркеры неопределённости пользователя: `примерно`, `около`, `кажется`.

### Шаг 6. Не потеряй старые записи

Это append-only операция.

Нельзя заменять файл новым коротким содержимым.

При update:

- сохранить YAML;
- сохранить все существующие события;
- добавить новые события;
- обновить `updated`;
- не менять старые события без отдельной команды.

### Шаг 7. Запиши напрямую в main

Для обычного capture-события:

- использовать `main`;
- не создавать ветку;
- не создавать PR;
- не создавать issue.

Commit message рекомендуется короткий:

`Log food/stoma entry YYYY-MM-DD HH:MM`

### Шаг 8. Подтверди только факт записи

Успешный ответ:

`Записано: HH:MM — питание.`

или для нескольких событий:

`Записано: HH:MM — питание; HH:MM — стома.`

Если commit не выполнен, нельзя говорить, что запись сохранена.

## Жёсткие запреты

В capture-only режиме без отдельного запроса пользователя запрещено:

- анализировать связь еды и стомы;
- оценивать состояние здоровья;
- давать рекомендации;
- искать информацию в интернете;
- читать научные источники;
- считать калории;
- считать суточный объём;
- сравнивать с предыдущими днями;
- обновлять медицинские гипотезы;
- писать длинный ответ;
- задавать уточняющий вопрос ради необязательной детали;
- менять любой файл вне `09 Ежедневный контроль/Питание и стома/`.

Исключение — только обязательная медицинская безопасность при явной непосредственной угрозе жизни.

---

## Коррекция записи

Если пользователь говорит:

`исправь прошлую запись: было 350 мл, а не 250`

разрешено изменить только явно указанное прошлое событие.

Перед исправлением:

1. прочитать дневной файл;
2. найти однозначно соответствующее событие;
3. изменить только названное поле/фрагмент;
4. сохранить остальной файл без изменений;
5. коротко подтвердить исправление.

Если невозможно однозначно определить, какую именно запись исправлять, тогда допустим один короткий уточняющий вопрос.
