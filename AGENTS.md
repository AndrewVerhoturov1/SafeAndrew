# SafeAndrew — договор для агентов

> [!IMPORTANT]
> Это персональная медицинская база знаний и хранилище Obsidian. Главная цель — точная, проверяемая и полезная картина здоровья пользователя.

## 1. Основные факты

```text
repository: AndrewVerhoturov1/SafeAndrew
primary branch: main
large-task branch: feature/YYYYMMDD-short-kebab-slug
human language: Russian
vault: Obsidian
```

## 2. Обязательный путь чтения

Для обычных задач:

1. `AGENTS.md`.
2. `system/repo-context.yaml`.
3. `00 Главная.md`.
4. `system/medical-domains.yaml`.
5. `STATUS.md` нужного медицинского направления.
6. Только относящиеся к задаче первичные документы и научные источники.
7. Нужную инструкцию из `.agents/skills/SKILLS_INDEX.md`.

### 2.1. Специальный короткий маршрут: голосовая capture-запись

Если пользователь коротко сообщает:

- что он съел или выпил;
- что вышло по стоме;
- новый или изменившийся симптом;
- общее самочувствие;

и **не просит отдельно анализ**, включается capture-only режим.

В этом режиме полный маршрут выше **не нужен**. Прочитать только:

1. `AGENTS.md`;
2. `system/voice-food-stoma-capture-contract.md`;
3. `.agents/skills/capture-food-stoma-entry/SKILL.md`;
4. текущий файл `09 Ежедневный контроль/Питание и стома/YYYY-MM-DD.md`, если он существует.

Затем выполнить только:

```text
capture → write → confirm → stop
```

Не читать научную базу, гипотезы, медицинскую картину или постоянные карточки симптомов и не добавлять анализ/советы, если пользователь их отдельно не запросил.

## 3. Доказательность

- Не смешивать первичные документы, сводки, гипотезы и советы.
- Любое медицинское утверждение привязывать к конкретному документу или научному источнику.
- Указывать дату, единицы измерения и лабораторные нормы.
- Явно отмечать уровень уверенности и недостаток данных.
- Не считать гипотезу диагнозом.
- Не исправлять содержание первичного документа без отдельной пометки об ошибке распознавания.
- Более новый документ не отменяет старый автоматически: описывать изменение во времени.

## 4. Медицинская безопасность

- Не назначать рецептурные препараты и не менять дозировки как установленный факт без врача.
- Отделять: самонаблюдение, плановое обращение, срочная помощь.
- При возможной непосредственной угрозе жизни давать понятный призыв обратиться за экстренной помощью.
- Не скрывать неопределённость убедительным тоном.

Capture-only режим не отменяет это правило. При явной непосредственной угрозе жизни факт по возможности сохраняется, после чего даётся короткое обязательное safety-сообщение.

## 5. Работа с Git

- Записи пользователя через Obsidian могут попадать прямо в `main`.
- Небольшие очевидные правки агента допустимы в `main`.
- **Capture-only записи питания/стомы/симптомов/самочувствия** по `system/voice-food-stoma-capture-contract.md` пишутся напрямую в `main` без отдельной ветки или PR.
- Структурные, исследовательские и массовые изменения выполнять в отдельной ветке.
- Одна задача — одна ветка.
- Перед работой определить точный исходный коммит.
- Не изменять один файл одновременно несколькими агентами.
- Перенос крупной задачи в `main` выполнять после проверки пользователем.

## 6. Оформление Obsidian

- Использовать свойства YAML по схеме [[system/metadata-schema|metadata-schema]].
- В длинных документах делать содержание с якорными ссылками.
- Использовать внутренние ссылки `[[Файл#Раздел|Название]]`.
- Один факт хранить в одном каноническом месте, в остальных местах ставить ссылки.
- Для постоянной машинной ссылки использовать латинское поле `id`.
