# Питание и стома — журнал

Этот каталог предназначен для частых коротких записей пользователя о:

- еде;
- напитках;
- выходе по стоме;
- наблюдаемых характеристиках отделяемого.

## Формат дневного файла

```md
---
id: food-stoma-log-2026-08-27
ntype: daily-health-log
date: 2026-08-27
status: active
updated: 2026-08-27
---

# Питание и стома — 2026-08-27

## События

- 09:12 — **Питание:** омлет из 2 яиц, тост.
- 09:15 — **Питьё:** чай.
- 10:03 — **Стома:** около 250 мл; жидкое; светло-коричневое.
```

Главное свойство формата — **append-only**: новые события добавляются, старые не исчезают.

---

## Категории событий

Используются три базовые категории:

- `Питание`
- `Питьё`
- `Стома`

Не создавать новые категории без необходимости. Дополнительные детали сохранять внутри строки события.

Пример:

```md
- 13:40 — **Стома:** около 300 мл; кашицеобразное; газ; после записи заменён мешок.
```

---

## Временная точность

Если событие текущее и пользователь не назвал время — используется текущее локальное время сообщения.

Если время названо явно — используется время пользователя.

Если указано только `утром`, `вечером` и т. п., точное время не придумывается:

```md
- утро (точное время не указано) — **Питание:** овсянка и банан.
```

---

## Что здесь не хранится автоматически

Без отдельной команды пользователя сюда не добавляются:

- медицинская интерпретация;
- выводы о причинах;
- советы;
- калорийность;
- рассчитанный водный баланс;
- суточные суммы;
- тренды;
- диагнозы;
- гипотезы.

Этот каталог — **сырой хронологический журнал пользовательских наблюдений**.

Анализ этого журнала является отдельной задачей.

---

## Git-правило

Обычные записи питания/стомы являются повседневным capture и пишутся напрямую в `main` согласно `system/voice-food-stoma-capture-contract.md`.

Модель не создаёт отдельную ветку или PR для каждой записи.

---

## Исправления

Если пользователь явно исправляет прошлое событие, изменяется только соответствующая запись.

Пример:

`Исправь последнюю стому: 350 мл, а не 250 мл.`

Нельзя использовать коррекцию одного события как повод редактировать другие записи дня.
